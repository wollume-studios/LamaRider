Metalama tooling for Rider: see which aspects touch your code, what they generate, test them and debug them. The Rider counterpart of the Visual Studio extension "Metalama Tools".

LamaRider tool window

Every aspect class of the solution and its packages, filtered by name and grouped by project/package, by namespace or not at all, with its documentation and Go to source (library aspects open their sources or decompiled code). Select one to see every target (project, namespace, type, member) with the transformations it causes and the diagnostics it reports. Track Caret shows the aspects affecting the code at the caret instead. The window refreshes on its own after saves, builds and package changes.

Code Vision and transformed code

  • Above every declaration an aspect touches: transformed code for aspects you see as attributes, the names of the others, N aspects for more than two; applied to N targets above aspect classes. The tooltip gives each aspect's origin (attribute, fabric, inherited, ...) and documentation. Aspects a fabric puts on a parameter get an inlay hint.
  • A click shows the aspects grouped by member, parameter and return value. Clicking an aspect goes to its source (also SourceLink or decompiled), shows it in the LamaRider window, or asks: your choice in the settings.
  • Show Transformed Code (also a click on transformed code): the transformed code of one declaration in a popup, highlighted, with a toggle to diff it with the source, the whole file in Metalama Diff, and links to its aspects.
  • Metalama Diff: source and transformed code of a whole file side by side.

T# template highlighting

Compile-time code in templates is tinted; meta.* and compile-time variables stand out (Settings › Editor › Color Scheme › Metalama T#).

Metalama errors

  • Errors such as LAMA0037 are underlined from LamaRider's own analysis seconds after a save, also while Rider's own Metalama analysis waits for a build (LAMA0118).
  • Errors without a location (e.g. an exception in a fabric) show in an info bar on C# editors, with the LAMA documentation and a build, and are underlined on your aspect classes.
  • Alt+Enter in aspect and template code: Build project to resume Metalama analysis (LAMA0118), or build on save.

Aspect tests

Alt+Enter on an aspect class: Create Metalama aspect test adds a prefilled test file to the aspect test project next to the aspect's project, creating the project when there is none. Run or debug the test from the gutter icon or the context menus, then Accept Metalama Test Output saves its output as the expected .t.cs. While debugging, breakpoints in your aspects, templates and fabrics stop, no Debugger.Break() needed. Rider's Test Runner discovery, which aspect tests need, is set up for you.

Debugging transformed code

Debug with LamaDebug selects Metalama's LamaDebug configuration (adding it to the .sln or .slnx when missing) and starts debugging: step into aspect code or set breakpoints in the transformed files. Or debug transformed code in every build configuration, with or without formatting it (LAMA0066).

Settings

Settings › Tools › LamaRider: what clicking an aspect does, build after aspect changes, debug and format transformed code, and the Rider setup Metalama aspect tests need (shows whether it is in place).
